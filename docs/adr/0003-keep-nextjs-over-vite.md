# ADR-0003: 프레임워크로 Next.js 유지 (vs Vite)

- 상태: 채택
- 날짜: 2026-07-21
- 관련: [0001](0001-app-only-webview-delivery.md), [0002](0002-static-export.md)

## 맥락

ADR-0001·ADR-0002에 따라 우리는 **앱-only + Static Export**다. 즉 Next의 서버 기능(SSR·미들웨어·Server Actions 등)을 거의 쓰지 않는다. 자연히 **"그럼 Vite + React Router가 더 낫지 않냐"** 는 정당한 의문이 생긴다. SEO 근거가 폐기된(ADR-0001) 지금, Next를 유지할 이유를 정직하게 재점검한다.

## 결정

**Next.js를 유지한다.** 근거(SEO 제외):

1. **포트폴리오 신호** — Next.js App Router 숙련은 프론트엔드 채용 시장의 사실상 표준이다. 이 프로젝트의 목적이 취업 포트폴리오이므로 이 신호 가치가 크다.
2. **이미 세팅·빌드 통과** — Static Export, 폰트, FSD, 토큰까지 구성 완료. 전환은 순손실(churn)이다.
3. **라우팅/레이아웃 시스템** — 파일 기반 라우팅과 중첩 레이아웃이 `(tabs)`/`(full)` 구조에 관례로 딸려온다(Vite면 수동 배선).
4. **빌드타임 프리렌더** — 정적 콘텐츠를 HTML로 구워 오프라인/즉시표시에 유리.

## 결과

**긍정**: 위 근거들.

**부정 / 트레이드오프 (정직하게)**
- 순수 앱-only 관점에서 **Vite가 더 가볍다.** Next의 상당 기능이 미사용 상태로 남는다. 이 무게를 감수한다.

## 고려한 대안

- **Vite + React Router**: 더 가볍고 빌드가 단순하나, 포트폴리오 신호가 약하고 이미 구성된 것을 버리는 순손실. 앱-only가 "가벼움 최우선"으로 재정의되면 재검토할 수 있다.
