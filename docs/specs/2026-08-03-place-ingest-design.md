# 장소 원장 시딩 설계 — LOCALDATA 3업종 전국 (#44)

> 2026-08-03 브레인스토밍 확정. M3 지도 트랙의 첫 작업 — **화면보다 데이터가 먼저다.**
> 지도 화면 설계(마커 밀도 → 클러스터링 여부, 카테고리 비율 → 필터 UI)가 실데이터 분포에 좌우된다.

## 0. 선행 결정 — 지도 라이브러리는 카카오맵

이 스펙의 범위는 아니지만 같은 브레인스토밍에서 확정했고 수집 설계의 전제라 기록한다.

- **카카오맵 확정.** Korea-only 서비스라 구글맵의 유일한 실질 우위(다크모드 Cloud Styling)가 나머지 열세(한국 지도 품질·무료 쿼터·사용자 친숙도)를 못 이긴다.
  - 무료 쿼터: 카카오 JS SDK **하루 30만 건** vs 구글 동적 지도 **월 1만 로드**(2025 개편). 초과 단가도 0.1원/건 vs 약 $7/1,000.
  - **2026-07-21 카카오 쿼터 정책 변경 주의**: 개발자 계정의 **첫 번째 활성화 앱에만** 무료 쿼터. → 지호님 계정에서 별별펫이 첫 활성화 앱인지 확인 필요.
  - 다크모드 미지원은 수용: 지도 면만 라이트로 두고 크롬·오버레이만 다크 (CSS invert 핵은 라벨이 깨져 불채택).
- **카카오맵은 렌더링 전용**(약관 — 좌표·리뷰·평점을 우리 DB에 저장 금지, CLAUDE.md). 그래서 원장은 공공데이터로 채운다 — 이 스펙이 그 일이다.
- 구현 시 JS 키 SDK 도메인 등록: 개발 `http://localhost:3000` + 앱 WebView origin(Capacitor 안드로이드 `https://localhost`). `file://` 미지원이지만 Capacitor는 http(s) 스킴이라 해당 없음.

## 1. 목표와 범위

`places`(현재 0행)를 행안부 LOCALDATA 인허가 데이터로 채운다.

- **범위**: 3업종 **전국** 전부 — 동물병원(`animal_hospital`)·동물미용업(`grooming`)·동물위탁관리업(`boarding`). `place_category` enum과 1:1.
- **접근법 C(하이브리드)**: v1은 로컬 스크립트로 시딩. 증분 갱신 자동화(Edge Function + cron)는 로드맵.
- **v1 제외** (§8 로드맵): 특수동물 태깅(`place_species` — 원장이 있어야 설계 가능한 별도 트랙), 검역본부 데이터 병합(LOCALDATA와 중복 해소 비용), 지오코딩 좌표 보완.

## 2. 데이터 획득

- **LOCALDATA 사이트(localdata.go.kr)는 2026-04-16 폐쇄됐고** 지방행정 인허가 데이터는 공공데이터포털(data.go.kr)로 이관됐다(2026-08-03 실측 — 학습 시점 지식이 낡아 있었다). "LOCALDATA"라는 이름은 이 데이터 계열의 관용 명칭으로만 쓴다.
- 공공데이터포털에서 업종별 **전국 파일데이터(CSV)를 수동 1회 다운로드**해 스크립트 입력으로 준다. 셋 다 로그인 불필요·이용허락 제한 없음, 좌표는 여전히 EPSG:5174(위탁관리업 페이지에서 실측 확인, 2025-11-27 갱신본):
  - 동물병원: <https://www.data.go.kr/data/15045050/fileData.do>
  - 동물미용업: <https://www.data.go.kr/data/15107032/fileData.do>
  - 동물위탁관리업: <https://www.data.go.kr/data/15107029/fileData.do> (전국 7,887행)
- Open API(인증키·페이징)는 쓰지 않는다 — 증분 갱신 단계(로드맵)의 도구다.
- 원본 파일은 `data/`에 두고 **gitignore** — 퍼블릭 저장소에 수집 데이터를 올리지 않는다(CLAUDE.md). 저장소에는 스크립트·타입·샘플 픽스처만.

## 3. 정제 규칙

### 3-1. 컬럼 매핑

| LOCALDATA | places | 비고 |
|---|---|---|
| 관리번호 | `external_id` | `source='localdata'` 고정. `UNIQUE (source, external_id)` 실재 확인(2026-08-03) |
| 사업장명 | `name` | |
| 도로명전체주소 | `road_address` | 결측 흔함 — nullable |
| 소재지전체주소 | `jibun_address` | 〃 |
| 소재지전화 | `phone` | 〃 |
| 좌표정보(X/Y) | `lat`/`lng` | EPSG:5174 → WGS84 변환 (§3-2) |
| 영업상태 | `status` | 영업/정상→`operating`, 휴업→`suspended`, 폐업→§4-2 |

- 실제 컬럼명은 업종 파일마다 다를 수 있어 구현 시 헤더를 실측해 매핑 상수로 고정한다. **영업상태 값 집합도 실측해 상수로 고정**하고, 매핑에 없는 미지의 값은 조용히 `operating`이 되지 않도록 **스킵+카운트**한다.
- **인코딩**: LOCALDATA CSV는 EUC-KR(CP949)이 흔하다. 파싱 전에 인코딩을 확인·변환한다.

### 3-2. 좌표

- **EPSG:5174(중부원점TM) → WGS84** 변환은 proj4로 한다.
- 변환 결과가 **한국 상자(위도 33~39, 경도 124~132) 밖이면 변환 오류로 간주해 스킵+카운트**. DB의 `places_lat_lng_range_check`는 세계 범위(±90/±180)라 스크립트가 걸러야 한다. geography 캐스트는 범위 초과를 에러 없이 wrap하므로(supabase-convention) DB에 맡기면 조용히 어긋난다.
- 좌표 결측 행도 스킵+카운트. **지오코딩 보완은 v1 제외** — 하게 되면 공공 VWorld로 한다. 카카오 지오코딩 결과를 DB에 저장하는 것은 약관 위반 소지가 있어 쓰지 않는다.

## 4. 적재

### 4-1. upsert

`on conflict (source, external_id) do update` — 재실행이 곧 갱신이다. 배치 chunk로 나눠 넣는다(PostgREST 요청 크기 한계 고려, 구체 수치는 구현 시 실측).

### 4-2. 폐업 처리 — 2단계

LOCALDATA 인허가 파일은 폐업 이력 전체를 포함한다(폐업 행이 영업보다 많을 수 있다).

1. **신규 적재는 영업·휴업만.** 최초 시딩에서 폐업 대량 행을 원장에 넣지 않는다.
2. **기존 행의 폐업 전환은 `status='closed'` 갱신.** 원장에 있던 장소가 이후 데이터에서 폐업으로 나오면 행을 지우지 않고 상태만 바꾼다.

**행 삭제는 하지 않는다.** `reviews.place_id`가 `ON DELETE CASCADE`라(2026-08-03 실측) 장소 행 삭제는 사용자 리뷰(UGC) 파괴다. 고아 리뷰는 FK가 있는 한 발생 자체가 불가능하므로 "고아 방지를 위한 삭제"는 성립하지 않는다. RPC(`nearby_places`)가 기본으로 `operating`만 반환하니 closed가 화면을 오염시키지도 않는다. **리뷰 0개인 closed 행만 주기 청소**하는 것은 허용(지울 UGC가 없다) — 로드맵의 cron 작업.

## 5. 스크립트 구조 — `scripts/ingest-places/`

앱(FSD `src/`)과 분리된 도구 코드. 단일 책임으로 쪼갠다.

| 파일 | 책임 |
|---|---|
| `parse.ts` | CSV 읽기 + 인코딩(EUC-KR→UTF-8) + 행 파싱 |
| `transform.ts` | 컬럼 매핑·좌표 변환·범위 검증·status 매핑. **순수 함수 — 테스트 대상** |
| `load.ts` | Supabase `service_role`로 배치 upsert |
| `index.ts` | CLI 진입점(파일 경로 인자) + 처리/스킵 사유별 카운트 리포트 |
| `fixtures/` | 샘플 몇 행(개인정보 없는 행) — 커밋 대상 |

- 키: `.env.local`의 `SUPABASE_SERVICE_ROLE_KEY`. **`NEXT_PUBLIC_` 접두사 금지, 앱 코드에서 import 금지** — scripts 전용.
- 테스트: vitest — `transform` 단위 테스트(알려진 좌표쌍 변환값, status 매핑, 한국 상자 밖 스킵, 결측 스킵).

## 6. 시딩 후 검증

- SQL 실측: 총 행수, 카테고리·status 분포, `min/max(lat, lng)`가 한국 상자 안, `geog is not null` 전수.
- `nearby_places` 실호출 스모크: 서울 도심 반경 3km 병원 수가 상식적인지.
- `explain (analyze, buffers)`로 **GIST 인덱스를 실제로 타는지 실측** — supabase-convention 3-3의 첫 실전. 통계 갱신(`analyze public.places`) 후 측정한다(플래너 기본 추정치 함정).
- 처리/스킵 리포트를 이슈 #44에 기록한다.

## 7. 에러 처리 원칙

- 행 단위 오류(파싱 실패·좌표 오류·필수 결측)는 **스킵하고 사유별 카운트** — 한 행 때문에 전체를 죽이지 않는다.
- 파일 단위 오류(인코딩 판별 실패·헤더 불일치)는 **즉시 중단** — 잘못된 매핑으로 수만 행을 넣는 것이 최악이다.
- upsert 실패 chunk는 재시도 없이 중단하고 보고 — 원인(제약 위반 등)을 눈으로 확인한 뒤 재실행한다(재실행 안전이 설계돼 있으므로 부분 적재 상태는 문제가 아니다).

## 8. 로드맵 (v1 제외, 순서 미정)

- 증분 갱신 Edge Function + cron — 폐업 상태 갱신, 리뷰 0개 closed 청소
- 특수동물 태깅 트랙(`place_species`) — 해자의 본체, 원장 확보 후 별도 브레인스토밍
- 검역본부 영업장 데이터 병합(중복 해소 설계 필요)
- VWorld 지오코딩으로 좌표 결측 보완
