# 지도 화면 + 장소 상세 설계 (#48)

> 2026-08-03 브레인스토밍 확정(Visual Companion 목업 선택 포함). M3 본편 — 장소 원장 34,832행(#44)과
> `nearby_places` RPC(#8)의 첫 소비처. 선행 결정: 카카오맵 확정 근거는 [장소 시딩 스펙 §0](2026-08-03-place-ingest-design.md).

## 1. 지도 화면 (`/map`, (tabs) 셸)

**뼈대 — 풀 지도 + 바텀시트** (목업 B안 채택. 추후 카카오맵풍으로 구조 진화 여지를 열어둔다):

- 지도가 화면 전체를 채우고, 그 위에 세 층이 뜬다:
  1. **상단 카테고리 칩 열** — `전체 · 병원 · 미용 · 호텔 · 약국 · 장묘`. **단일 선택**(하나 탭 → 그 업종만, 다시 탭 → 해제=전체). 카카오맵·당근·네이버지도의 표준 패턴이고 `nearby_places(p_category)` 단일값 시그니처와 일치한다.
  2. **현위치 버튼** — 우측, 바텀시트 접힌 높이 위.
  3. **바텀시트 리스트** — "근처 N곳" 헤더 + 장소 행(이름·카테고리 태그·거리·주소). 접힌 상태로 항상 걸쳐 있고 드래그로 확장. **vaul 이 아니라 커스텀 시트다** — vaul 은 `modal` 을 Radix Root 에 전달하지 않아(구현 중 소스 실측) 상시 비모달 시트에서 앱 전체 aria-hidden·body pointer-events:none 이 걸린다. 포털 없는 순수 div + 포인터 드래그 + `aria-expanded` 핸들 버튼(키보드 대체 경로). 행 탭 → 상세 이동.
- **마커 탭** → 해당 핀 확대(선택 상태) + **접힌 바텀시트 상단이 그 장소의 프리뷰 행으로 바뀐다**(시트를 올리면 전체 리스트로 복귀). 프리뷰 행/리스트 행 탭 → 상세.

**재검색 정책**:

- 최초 진입: 현위치 기준 **1회 자동 검색**. 위치 거부/실패 시 **서울시청 폴백** + 문구 안내(APP_MESSAGE).
- 이후 지도를 이동하면 **"이 지역 재검색" 버튼**이 떠서 누를 때만 재호출. idle 자동 재검색은 하지 않는다(호출 예측 가능성·쿼터·마커 안정성).
- 반경: 지도 뷰포트에서 계산(중심~모서리 거리), RPC 가 20km 로 clamp 한다. 초기 줌은 반경 약 3km.

## 2. 마커 — 물방울 핀 + 카테고리 5색

목업 B안(물방울) 채택. "여기"를 가리키는 꼬리가 있는 클래식 핀.

- **SVG 로 그려 `MarkerImage` 로 등록**한다 — HTML CustomOverlay 가 아니라 Marker 라야 SDK **클러스터러**를 그대로 쓸 수 있다. 도심 밀집(서울시청 3km 221곳 실측) 때문에 클러스터러는 v1 포함.
- 카테고리 색 + **흰 아이콘 병행**(색상 단독 정보 전달 금지 — CLAUDE.md). 선택된 핀은 확대.
- 색 초안(브레인스토밍 합의, 최종은 토큰으로 확정하며 라이트/다크 실측): 병원 로즈 `#E5484D` · 약국 그린 `#30A46C` · 미용 핑크 `#D6409F` · 호텔/위탁 블루 `#0091FF` · 장묘 슬레이트 `#7E808A`.
- **토큰 규칙과의 관계**: "크롬 무채색" 규칙은 헤더·탭바 대상이다. 마커는 콘텐츠(정보/의미 층)라 카테고리 색이 규칙에 부합한다. 색값은 `globals.css` 에 `--place-*` 시맨틱 토큰으로 정의하고 컴포넌트에 HEX 를 직접 쓰지 않는다. SVG MarkerImage 는 CSS 변수를 못 읽으므로 **토큰 값을 단일 상수 모듈에서 공유**한다(6-1 표에 예외 등재).

## 3. 장소 상세 (`/place?id=`, (full) 셸) — A+B 하이브리드

목업 A(미니 지도 헤더) + B(정보 리스트)를 세로로 합친다. 별도 CTA 버튼은 없다.

1. **미니 지도 헤더** — 해당 좌표 중심, 드래그·줌 잠금. 탭하면 지도 탭으로 이동해 그 장소 포커스.
2. 이름 + 카테고리 태그(`bg-primary-tint` 아님 — 카테고리 칩은 §2 색 체계의 tint) + 영업 상태(색+텍스트).
3. **정보 행 리스트**: 도로명 주소(길게 눌러 복사 가능한 일반 텍스트) / 지번 주소 / **전화번호 행 = `tel:` 링크**(탭하면 바로 통화 — WebView 에서 네이티브 다이얼러) / "지도에서 보기".
4. **후기 그릇** — "후기 — 준비 중" placeholder. M4 에서 채운다(그릇 먼저 규칙).

- 라우팅: Static Export 라 동적 세그먼트 불가 — **`/place?id=` 쿼리 라우트**. `/pet/edit?id=` 와 같은 확립 패턴: `Suspense` + `useSearchParams`, id 없음/조회 실패 시 동일 문구(존재 여부 비유출), ErrorState + 재시도.
- 전화번호 결측(원장 6.5%)이면 전화 행 자체를 숨긴다.

## 4. FSD 배치

| 위치 | 책임 |
|---|---|
| `entities/place` | RPC 반환 타입의 **nullability 복원**(supabase-convention §1 — `phone`·주소·`external_id` 는 실제 NULL) + `use-query-nearby-places`(p_lat·p_lng·p_radius_m·p_category) + `use-query-place`(id 단건 — `.from('places')` 단순 select, RPC 불필요) + 카테고리 라벨·색 상수 |
| `widgets/place-map` | 카카오 SDK 캡슐화 — 스크립트 로드 훅, 지도 컨테이너, 마커/클러스터러, 미니 지도 모드(조작 잠금). 지도 화면과 상세가 공용 |
| `views/map` | 화면 조립 — 칩·현위치·재검색·바텀시트 |
| `views/place-detail` | 상세 조립 — 미니 지도·정보 행·후기 그릇 |

의존 방향: `views → widgets → entities → shared` 준수. 커뮤니티 글처럼 카테고리는 값이지 폴더가 아니다.

## 5. 카카오맵 SDK

- JS SDK 를 스크립트 로드 훅으로 지연 로드. 앱 키는 `NEXT_PUBLIC_KAKAO_MAP_KEY` — JS 키는 도메인 등록으로 보호되는 공개 설계값이라 `NEXT_PUBLIC_` 이 맞다.
- **지호님 액션**: 카카오 개발자 콘솔에서 ① JS 키 발급 ② SDK 도메인 등록 — `http://localhost:3000`(개발)·`https://localhost`(Capacitor 안드로이드 WebView) ③ 별별펫이 계정의 "첫 활성화 앱"인지 확인(2026-07 쿼터 정책).
- `react-kakao-maps-sdk` 채택 여부는 **구현 직전 Context7 로 최신 상태 확인 후 결정**(AGENTS.md 규칙). 직접 SDK 를 다뤄도 widgets/place-map 안에 갇힌다.
- 지도 렌더링은 표시 전용 — 카카오 좌표·장소 데이터를 우리 DB 에 저장하지 않는다(약관, CLAUDE.md).

## 6. 다크 모드·접근성

- 지도 면은 라이트 유지(카카오 다크 미지원 — 시딩 스펙 §0). 칩·바텀시트·상세·버튼은 다크 대응. 지도는 콘텐츠 면이라 이질감이 적다는 판단 — 에뮬레이터 실측으로 재확인.
- 칩·리스트 행·버튼 최소 44px 탭 영역. 마커는 SDK 렌더라 44px 보장이 어려워 **바텀시트 리스트가 동등한 대체 경로**(모든 장소가 리스트로 접근 가능).
- 핀 색상은 아이콘 병행. 상태(영업/휴업)는 색+텍스트.
- 바텀시트·칩의 스크린리더 라벨, 재검색 버튼 `aria-live` 결과 안내는 구현 계획에서 구체화.

## 7. 에러·엣지

- 위치 권한 거부: 서울시청 폴백 + 문구. 재요청 버튼은 현위치 버튼이 겸한다.
- RPC 실패: 바텀시트 영역에 ErrorState + 재시도(기존 패턴).
- 결과 0곳: "이 지역에는 아직 등록된 곳이 없어요" 빈 상태 문구.
- SDK 로드 실패(도메인 미등록·네트워크): 지도 영역 ErrorState + 재시도.
- 상태 필터: `p_statuses` 는 기본값(operating만) 사용. 휴업 뱃지는 로드맵.
